# 대시보드에서 내 환경 구성하기

## 새 컴퓨터의 진입점

처음 실행할 Git·Python 3.10 이상과 checkout은 한 번 준비해야 한다. Windows는 WSL 안에서 실행한다.
이후에는 대시보드의 **내 환경**에서 설치·설정·인증·업데이트를 이어간다.

1. **설정 가져오기·내보내기**에서 기존 컴퓨터의 설정 JSON을 불러오거나 **도구·설정 선택**으로 필요한 것을 고른다.
   내보내기에는 기존 bws 등록 키의 참조도 포함되며 개인키·토큰·비밀번호 값은 포함되지 않는다.
   다른 컴퓨터의 절대 경로·프로필 폴더·기존 공개키 경로는 적용 전에 검토한다.
2. **선택한 설정 저장·적용**을 누른다. 선택한 설정을 저장한 뒤 없는 기본 도구·선택 도구를 설치하고 기존 bootstrap으로 적용한다.
   화면의 진행 상황에 실행 중·완료·조치 필요가 표시된다. 관리자 승인·지원하지 않는 패키지 설치는 안내를 수행한 뒤 다시 실행한다.
   새 터미널을 열어 적용된 셸을 확인한다. 실행 중인 기존 셸·remote URL·계정은 자동 변경하지 않는다.
3. **Bitwarden 연결하기**에서 마스터 비밀번호로 잠금을 해제한다. 처음 CLI에 로그인한다면 Bitwarden 계정의 개인 API 키도 입력한다.
   입력값은 로컬 서버에서 CLI의 환경변수로 전달하며 비밀번호·API 비밀·세션을 파일·로그·명령 인수에 남기지 않는다.
   터미널 방식은 연결 옵션에 남아 있지만 필수 흐름은 아니다.
4. **등록된 SSH 키 모두 공급**을 누른다. 기존 등록 목록과 저장된 SSH 키 참조를 중복 없이 가져와 agent에 공급한다. `bws` 실행은 필요하지 않으며 UI가 내부 Python 도메인 모듈을 호출한다.
   기존 agent 키는 재사용하고 TTL을 바꾸지 않는다. 별도 agent를 만들었다면 **원격 접속 → SSH agent**에서 소켓과 터미널 연결 방법을 확인한다.
5. 필요한 기능만 **서비스·프로젝트·원격 접속**에서 이어간다. 외부 서비스 관리와 개발 실행 도구는 설치·연결 버튼으로 준비한다.
   비공개 저장소를 받으려면 현재 Git 인증에 읽기 권한이 필요하다. 또는 환경변수 공급에 `GITHUB_TOKEN`/`GH_TOKEN`으로 Bitwarden 항목 하나를 등록하면, 연결 중 관리 모듈 clone에만 공급한다. Git 전역 계정·credential helper는 바꾸지 않는다. Jira·Google·Tailscale 등 서비스 자체의 로그인·승인은 사용자가 진행한다.

## 책임과 화면 배치

- **내 환경**: 중요한 적용 작업과 진행 상황, 현재 필요한 인증을 우선 배치한다. 넓은 화면에서는 적용·진행을 왼쪽, 필요한 인증을 오른쪽에 둔다.
- **원격 접속 → SSH agent**: 준비된 로컬 개인키 등록·소켓·유지 시간·해제. 저장소 연결은 필요 없다. Git도 이 agent를 사용할 수 있다. 접속 대상 설정과는 별도 화면이다.
- **비밀 관리 → Bitwarden 연결 설정**: 보관소 연결·잠금 해제·대시보드 세션 시간. 항목 생성·파일 등록·편집은 Bitwarden으로 이동한다.
- **비밀 관리 → SSH 키 가져오기·공급**: 저장소에서 키를 읽어 준비하고 선택한 agent에 공급한다.
- **환경변수 공급**: 선택한 보관 항목을 지정한 자식 프로그램의 환경에 전달한다.

상태·새로고침은 작은 상태줄에 두고 고급 옵션·추가 설정·업데이트는 펼침 메뉴로 둔다.
설치·configure의 완료, Bitwarden 연결, agent 공급, 실제 원격 서버 접근 성공은 구분한다.

## 업데이트와 복구

**환경 코드 업데이트 → 최신 변경 확인**은 현재 checkout의 origin 추적 브랜치를 fetch한다.
**업데이트 가져오기**는 로컬 수정이 없고 fast-forward가 가능할 때만 진행한다.
로컬 수정·갈라진 커밋은 reset·stash·자동 병합하지 않고 조치 필요로 표시한다.
업데이트한 대시보드 코드는 **업데이트 적용·대시보드 재시작**으로 다시 읽는다. 메모리의 Bitwarden 연결은 다시 필요하다.
공급한 agent 키는 재시작 뒤에도 유지 시간까지 남는다. 명시적인 해제는 대시보드가 추가한 키에만 적용하며 원래 있던 키와 인증 파일은 유지한다.

이 업데이트는 대시보드 checkout의 코드 업데이트다. 설치된 모든 패키지·운영체제를 일괄 업그레이드하는 버튼은 아니다.
작업 기록은 `~/.config/dotfiles/dashboard/environment-run.json`에 실행 결과만 저장한다.
중간에 서버가 꺼지면 중단됨으로 표시하고 다시 실행 시 이미 설치된 도구를 감지해 건너뛴다.
앱 실행기는 설치 작업이 진행 중이면 자동 종료를 미루고, 종료 버튼으로 진행 중 작업을 끊지 않는다.
