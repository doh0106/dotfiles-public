# Git과 SSH 접속 설정

Git → 원격 저장소 접근과 원격 접속 → SSH 접속 대상은 별도 목록이다.
연결은 서버 접속 설정이며 개별 프로젝트 저장소를 생성하지 않는다.

## 기존 SSH 설정 사용이 기본

새 SSH 연결은 `sshMode: system`을 명시한다. 서버 주소에는 DNS 이름·IP 또는 기존
`~/.ssh/config`의 Host 별칭을 입력한다. 사용자·키·agent·비밀번호·대화형 인증은
OpenSSH 설정과 서버 정책에 맡긴다. 공개키 경로나 비밀 항목 등록은 요구하지 않는다.
Git은 별도 `core.sshCommand`나 SSH 설정 파일을 생성하지 않는다. SSH 서버도 새 별칭을
만들지 않는다. 표시 이름은 대시보드에서 구분하는 이름이며 접속할 때는 기존 별칭을 쓴다.

기존 설정 위임만 사용하는 상태에서 configure를 실행하면 SSH 파일·링크·키 경로를
설치하거나 수정하지 않는다. 셸·Git의 선택 설정 적용은 별개다.

## 지정한 SSH 키 사용

원하는 연결만 지정 키 방식으로 바꿀 수 있다. SSH 사용자와 `.pub` 경로를 지정하면
해당 키를 선택하는 설정을 생성한다. 개인키가 이미 agent에 있다면 비밀 연동이 없어도
사용할 수 있다. 별도로 키를 공급받으려면 비밀 관리 → 공급·연동에서 항목을 선택한다.
연결 화면에는 Bitwarden 항목 설정을 넣지 않는다.

같은 폴더 규칙의 Git SSH 연결은 하나의 core.sshCommand를 공유하므로 기존 설정 위임과
지정 키 방식을 혼합하면 저장을 거부한다. 다른 폴더 규칙을 사용하거나 연결을 직접 선택한다.
원본 SSH 정책을 몰래 대체하지 않기 위한 제한이다.

## HTTPS와 API

HTTPS는 기본적으로 기존 Git 인증 도구를 사용한다. 필요하면 공급·연동에서 토큰이나
credential helper를 지정한다. PR·이슈 도구의 API 토큰도 별도로 연동한다.
GitHub·GitLab 제품 선택은 PR·이슈 도구를 사용할 때 필요하다. Tailscale 접속 준비는
원격 접속 → Tailscale·집 WSL에서 관리한다.

## 비밀 관리의 책임

- SSH 키 준비: 연결·항목 검색·공개키 저장·agent 공급·정책·접속 설정 연동을 순서대로 진행한다.
- 서비스 토큰: 항목을 선택해 HTTPS Git·API 또는 명시한 프로그램 환경변수에 공급한다.
- 일반 비밀번호 탭은 제공하지 않는다. 기존 참조는 데이터에 보존한다.
- 공급·연동: 어떤 연결·기능에 어떤 항목을 사용할지 정한다.
- 비밀 저장소: Bitwarden 같은 보관 인프라의 준비 방법을 관리한다. 현재 저장소 어댑터는
  Bitwarden이며 다른 저장소는 어댑터 추가가 필요하다. 실제 vault 로그인은 자동 실행하지 않는다.
- 키·세션 정책: 새로 로드하는 키의 수명과 이 도구가 준비한 세션의 정리 범위를 정한다.

`bin/secret_store.py`는 비밀 저장소 조회만 담당한다. `bin/auth.py`는 SSH 키 일치 확인·로드,
Git credential helper와 gh/glab 자식 프로세스 토큰 주입을 담당한다. 저장소 어댑터는 SSH에
키를 등록하거나 사용처를 결정하지 않는다.

## 기존 설정 보존과 확인

기존 schema 3 연결의 sshMode가 없으면 종전의 지정 키 동작을 유지한다. 기존 항목의
purpose가 없으면 종전 용도를 해석하며 읽는 것만으로 설정을 다시 쓰지 않는다.
방식을 바꿔도 이전 공개키·인증 참조는 보존하며 시스템 위임 중에는 사용하지 않는다.
일반 비밀번호와 명시적으로 다른 용도의 항목은 공급 목록과 백엔드 검증에서 구분한다.

폴더 규칙은 선택 사항이다. 지정한 폴더의 작성자·연결 적용과 서비스 로그인은 별개다.
기존 저장소 remote URL을 자동 변경하지 않으며 설정됨·공급 준비·서버 인증 성공은 각각
구분한다. 초안 검토·저장은 홈 설정 적용이나 로그인·키 로드를 자동 실행하지 않는다.

설정 파일은 고급 → 이 연결에 적용될 설정 파일 보기에서 미리 확인한다. 폴더 규칙을
공유하면 다른 연결 내용이 포함될 수 있다고 표시한다. 전체 생성 파일은 변경 검토·적용에서
저장된 결과와 현재 초안 미리보기를 구분한다.
