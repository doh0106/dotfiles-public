# Git 호스트와 원격 컴퓨터 연결

**Git 설정 → 원격 저장소 접근**과 **원격 접속 → SSH 접속 대상**은 별도 목록이다.
각 메뉴에서 연결을 추가하면 종류가 정해진다. 이름을 입력한 뒤 목록에서 이름·호스트·방식·
사용 상태를 보고 상세를 연다. Git 연결의 폴더별 작성자 설정은 선택 사항이다.

## 대상과 방식

| 접속 대상 | 설정할 방식 | 추가 항목 |
|---|---|---|
| Git 저장소 | SSH 또는 HTTPS | SSH는 로그인 사용자·공개키·인증 참조. HTTPS는 공개 읽기라면 인증 생략 가능 |
| SSH 서버 · 키 인증 | SSH | 서버 OS 사용자·공개키·인증 참조, 선택적인 터미널 별칭 |

GitHub·GitLab은 Git 저장소 접속 자체의 필수 분류가 아니다. PR·MR·이슈 API를 쓸 때만
**PR·이슈 도구 · 선택**에서 제품과 인증을 고른다. 일반 Git 호스트도 SSH/HTTPS로 쓸 수 있다.
Tailscale SSH는 **원격 접속 → Tailscale·집 WSL**에서 설정한다.

연결 상세는 접속할 서버, 접속 방식과 인증, 선택적인 폴더별 자동 적용으로 나눈다.
메뉴가 정한 접속 대상 종류는 입력칸으로 다시 노출하지 않는다. 연결 이름은 목록의 표시 이름이며,
SSH 사용자는 원격 서버 로그인 계정이다. Git 커밋 작성자나 Bitwarden 계정과 다르다.
SSH 별칭은 설정 적용 후 `ssh <별칭>`에 사용하는 이름이다.

## 프로필은 선택 사항

작업 프로필을 비워도 연결을 추가·저장·사용할 수 있다. 프로필이 없는 연결의 인증 준비는
`bws --connection ID`처럼 ID를 명시한다. 연결 ID는 자동 생성하며 상세 화면에서 확인한다.
Git은 연결별 설정 파일을 만들지만 임의 폴더에 자동으로 적용하지 않는다.
적용 안내의 `git -c include.path=…` 명령을 사용하거나 대상 저장소의 로컬 include에 명시한다.

프로필을 선택한 Git 연결은 기존처럼 지정 폴더에서 자동 선택한다. SSH 서버의 별칭은
폴더와 무관하다. 새 SSH 서버에 Git 프로필을 요구하지 않으며, 기존 분류가 있으면 읽기 전용으로 표시·유지한다. 기존 프로필과 인증 파일을 자동 삭제하지 않는다.

## 필수와 기존 값

입력 옆에 **필수**, **사용 시 필수**, **선택**을 표시한다. 사용을 꺼 둔 초안은 일부 값을
나중에 채울 수 있지만, 실제 사용할 때 필요한 항목은 사용 시 필수로 표시한다.
저장 전 상태는 화면 공통으로 표시한다. 저장값과 달라진 필드는 **이전 값 확인**에서
기존 값과 출처를 볼 수 있다. 예시 형식은 placeholder로, 필요한 설명은 해당 필드에 붙여
표시한다. 물음표 도움말은 호버·클릭·키보드로 열 수 있다.

공식 github.com·gitlab.com의 SSH 사용자는 빈 값에 한해 git을 제안한다. 기존 값을
덮어쓰지 않는다. 새 연결은 주소가 정해지기 전에는 SSH 사용자도 비워 둔다.
공개키 경로는 키 선택에 필요하므로 필수 조건을 유지한다. 같은 인증 참조를 쓰는 다른
연결의 공개키 경로가 하나로 확인되고 현재 값이 비어 있으면 명시적으로 가져올 수 있다.
Bitwarden 조회나 키 파일 읽기·복사는 실행하지 않는다. 접속 방식을 바꿔도 기존 인증
참조를 자동 삭제하지 않으며, 호환되지 않으면 변경이 필요하다고 표시한다.

**고급 → 이 연결에 적용될 설정 파일 보기**는 현재 초안을 검증한 뒤 해당 연결의 파일만
표시한다. 폴더 규칙이 있는 Git 연결은 공유 파일이므로 같은 규칙의 다른 연결이 포함될 수
있다고 명시한다. SSH 서버는 해당 별칭 블록만 보여준다. 전체 생성 파일은
**변경 검토·적용**에서 저장된 결과와 초안 미리보기를 구분해 볼 수 있다.

설정됨과 실제 인증 성공은 별개다. 기존 저장소 remote URL도 자동 변경하지 않는다.
