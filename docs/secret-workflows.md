# SSH 키 준비와 서비스 토큰 공급

비밀 관리는 Bitwarden을 대체하는 비밀번호 관리자가 아니다. 저장소에서 사용할 키·토큰을
선택해 작업 환경에 공급한다. 일반 비밀번호 탭은 없으며 기존에 저장한 일반 비밀번호
참조는 삭제하지 않고 보존한다.

## 처음 사용하는 컴퓨터

1. dotfiles 대시보드를 열고 **비밀 관리 → SSH 키 준비**로 간다.
2. 필요한 Bitwarden CLI·OpenSSH 도구를 설치하고 **연결 상태 갱신**을 누른다.
3. 처음에는 **기본 터미널 앱**을 선택한다. 설치된 Terminal·iTerm2·Ghostty 중에서 선택하면
   다음에도 유지한다. **로그인 명령 준비 · 실행하지 않음**을 누르면 iTerm2는 새 창에 명령만
   입력한다. Terminal·Ghostty는 명령을 복사하고 앱을 연다. 직접 붙여넣고 Enter를 눌러
   실행한다. 지원 앱이 없는 환경은 화면의 명령을 원하는 터미널에서 실행한다. 연결 요청은 5분 동안 한 번만 유효하다.
4. 처음 CLI에 로그인한다면 Bitwarden 계정 설정에서 개인 API 키를 준비해 터미널에
   client_id·client_secret을 입력한다. 이어서 마스터 비밀번호로 잠금을 해제한다.
   이미 로그인한 CLI는 계정을 바꾸지 않고 잠금 해제만 한다. 기존 계정의 서버 URL도 바꾸지 않는다.
5. **연결 상태 갱신**을 누른다. 대시보드 연결은 15분 동안 메모리에만 유지한다.
   마스터 비밀번호·API 비밀·BW_SESSION은 웹 화면·설정 파일·명령 인수에 넣지 않는다.
   연결 요청 파일에는 로컬 주소·도구 경로·CLI 저장 위치·일회용 요청 값만 들어 있다.
6. 로그인한 터미널은 해당 세션을 가진 작업용 셸로 유지된다. 이후 토큰 공급 명령도 이
   터미널에서 실행한다. 대시보드 연결 해제는 다른 터미널이나 CLI 계정을 로그아웃하지 않는다.

## SSH 키 준비

1. 항목 이름을 2자 이상 입력해 검색한다. 검색은 사용자가 요청할 때만 수행한다.
   HTTP 목록에는 이름·ID·항목 종류만 포함한다. CLI가 반환한 복호화된 자료는 서버에서
   처리하고 비밀 본문을 브라우저·로그·파일로 내보내지 않는다.
2. SSH Key 또는 기존 Secure Note 항목을 선택해 **공개키 준비**를 누른다.
   선택한 개인키에서 공개키를 추출하므로 키와 공개키가 짝인지 확인할 수 있다.
   추가 암호가 필요한 개인키는 이 자동 추출 경로에서 지원하지 않으며 기존 agent로 준비한다.
3. 공개키와 SHA256 지문을 검토하고 `.pub` 저장 경로를 지정한다.
   홈 안의 일반 파일만 사용하며 다른 공개키가 있는 파일과 심볼릭 링크는 덮어쓰지 않는다.
   같은 공개키가 이미 있으면 재사용한다. 개인키는 일반 파일로 저장하지 않는다.
4. 키 유지 시간을 60~86400초로 정하고 **SSH agent에 키 공급**을 누른다.
   현재 agent에 연결할 수 있으면 재사용하고, 없으면 대시보드가 전용 agent를 시작한다.
   동일한 키가 이미 있으면 TTL을 바꾸지 않는다. 새로 추가한 키만 정리 대상으로 기록한다.
5. 연결을 선택하고 **연결 초안에 반영**한다. 기존 SSH 설정 위임에서 지정 키 방식으로
   바뀌며, 키 참조와 공개키 경로가 설정된다. 전용 agent를 썼다면 IdentityAgent 소켓도
   해당 연결에만 지정한다. 기존 SSH 별칭을 감지했으면 서버 주소·사용자를 원본에서 가져온다.
6. **변경 검토·적용**에서 검토·저장하고 필요한 configure 안내를 실행한다.
   저장·파일 적용·agent 공급·서버 인증 성공은 서로 다른 상태다. 공개키를 GitHub나 원격
   서버에 등록하는 동작과 실제 네트워크 접속 시험은 자동 실행하지 않는다.
7. 작업 후 **이번에 추가한 agent 키만 해제**를 누른다. 메모리에서 이 대시보드가 추가한 키만 해제한다.
   Bitwarden 원본·로컬 `.pub`·GitHub 등록 키·저장한 접속 설정과 기존 agent의 다른 키는 유지한다.
   정상 종료 시에도 새로 추가한 키를 정리하고 직접 만든 agent는 비었을 때만 종료한다.
   전용 agent가 종료되면 키를 다시 공급해야 한다. 소켓 경로는 이 기기의 관리 폴더 안에 고정되어 일반적인 재시작에서는 접속 설정을 다시 바꾸지 않아도 된다.
   강제 종료나 시스템 장애 때는 설정한 키 TTL이 남은 수명을 제한한다.

## 기존 bws 등록 가져오기

**기존 bws 등록 키**에 `secrets.json`의 SSH 키 등록을 바로 표시한다. `DOTFILES_SECRETS_MANIFEST`가 있으면 해당 파일을 사용하고, 없으면 `DOTFILES_DIR`·현재 저장소·`~/dotfiles`·`~/.dotfiles`에서 목록을 확인한다.
홈 안의 소유자 파일만 제한된 크기로 읽으며 스크립트를 실행하거나 로그인하지 않는다. `ssh-add`용 `note`·`sshkey` 참조만 가져오고 파일 쓰기·환경변수 실행 항목은 제외 안내한다.

- **관리 설정에 가져오기**: 이름·종류를 관리 초안에 넣는다. 같은 항목·종류·용도의 참조가 있으면 재사용한다. 변경 검토에서 저장하며 원본 목록은 수정하지 않는다.
- **이 키 사용 · 기존 공개키 확인**: Bitwarden 연결 후 선택한 키만 읽어 공개키를 추출한다. 기존 SSH 설정의 공개키와 실제 내용이 일치하면 경로를 재사용한다. 파일명으로 연결을 추정하지 않으며 agent 공급은 별도로 실행한다.

따라서 기존 등록 키는 검색·재입력하지 않아도 되고 기존 `bws`도 계속 사용할 수 있다.

## 설정 이후 다시 작업할 때

화면은 **처음 한 번 · 키와 접속 설정 등록**, **작업할 때 · 인증 준비**, **작업 끝 · 이번에 추가한 agent 키 해제**를 구분한다.
상단에는 기존 SSH 설정과 저장한 연결의 공개키를 agent 목록과 대조해 준비 상태와 다음 할 일을 표시한다.
대시보드 또는 연결에 지정한 agent 기준이며 다른 터미널의 agent와 실제 서버 인증 성공은 별도다.

- **키 준비됨**: 다시 공급할 필요가 없다. Bitwarden 연결이 만료돼도 agent에 키가 남으면 준비된 상태다.
- **키 공급 필요 / agent 연결 필요**: Bitwarden을 연결하고 저장한 연결의 **저장한 이 키 다시 준비**를 누른 뒤 유지 시간을 확인해 **SSH agent에 키 공급**한다. 일치하는 기존 공개키 파일은 다시 저장하지 않는다.
- **공개키 파일 확인 필요**: 파일 경로와 공개키를 확인한다. 다른 키가 있는 파일은 자동으로 덮어쓰지 않는다.

`bws`는 이미 등록한 인증 설정을 사용하는 명령이다. 최초 항목 선택·공개키 파일 생성·접속 설정 저장까지 대신하지 않는다.
새 인증 구현의 Bitwarden 직접 공급 방식은 잠금 해제 후 키를 공급하지만, 대시보드가 지정한 agent 방식은 해당 agent의 키 유무만 확인한다.
대시보드 agent에서 키가 사라졌다면 이 화면에서 다시 공급한다. 기존 개인 dotfiles의 `bws`는 기존 `load-secrets.sh` 등록 목록을 공급하며 이 대시보드의 연결 상태를 갱신하는 명령은 아니다.

## 서비스 토큰

1. **서비스 토큰**에서 동일한 저장소 연결을 사용해 항목을 검색한다.
2. Secure Note 또는 Login 항목을 토큰으로 선택하고 한 줄 형식을 확인한다.
   형식 확인은 만료·권한·서버 인증을 증명하지 않는다. 토큰 본문은 표시하지 않는다.
3. 공급 경로를 선택한다.
   - HTTPS Git·GitHub/GitLab API: 연결과 기능을 선택한다. HTTPS에는 서비스가 요구하는
     사용자명이 필요하다. 저장·적용 후 Git credential helper 또는 bwgh/bwglab가 선택한
     호스트의 자식 프로세스에 토큰을 전달한다.
   - 다른 프로그램의 환경변수: SERVICE_TOKEN 같은 변수 이름을 정하고 참조를 저장한다.
     로그인한 작업용 터미널에서 표시한 secret_supply.py 명령의 PROGRAM·ARGUMENTS를
     실제 프로그램과 인수로 바꿔 실행한다. 해당 프로그램이 지정한 변수를 읽어야 한다.
4. 일반 프로그램 공급은 선택한 명령의 자식 환경에만 토큰을 넣는다. Bitwarden 세션과
   다른 *_TOKEN 변수는 전달하지 않는다. 부모 셸·파일·서버 인증 설정은 변경하지 않는다.
   기존 Jira·Confluence netrc나 Google 인증 선택을 자동으로 교체하지 않는다.

## 구현 책임과 보존

- secret_store.py: 비밀 저장소 어댑터. 현재 Bitwarden을 지원한다.
- secret_session.py: 사용자 터미널에서 로그인·잠금 해제하고 일회용 연결 요청을 완료한다.
- secret_workflow.py: 수명 제한 세션, 검색 메타데이터, 공개키 파일 준비, agent 공급·정리를 관리한다.
- auth.py: 키 검증·로딩과 기존 Git/API 자식 프로세스 토큰 공급을 담당한다.
- secret_supply.py: 저장한 토큰 참조를 사용자가 명시한 프로그램의 환경변수로 공급한다.

기존 SSH·Git·셸 설정과 Bitwarden 계정은 읽기·화면 진입만으로 변경하지 않는다.
시스템 SSH 위임은 새 연결의 기본이며 비밀 등록을 요구하지 않는다. 지정 키 전환·공급·파일
저장·정리는 각각 사용자가 명시적으로 실행한다. 기존 일반 비밀번호 참조는 화면에서 숨기되
원본 데이터에 보존하며 SSH·Git·API로 자동 공급하지 않는다.
