# SSH 키 공급·환경변수 공급·Bitwarden 연결 설정

비밀 관리는 값을 보관하는 Bitwarden과 값을 사용하는 프로그램 사이의 공급을 담당한다.
SSH 서버·Git 호스트·사용자·공개키 경로·연결별 인증 선택은 Git 또는 원격 접속에서 관리한다.
기존 SSH·Git·셸 설정과 인증은 화면 진입이나 공급 목록 변경만으로 교체하지 않는다.

## Bitwarden 연결 설정

기본 경로는 UI의 **잠금 해제하고 연결**이다. 마스터 비밀번호와, CLI 첫 로그인에 필요한 개인 API 키를 입력한다.
항목 생성·편집·파일 등록은 Bitwarden에서 진행한다. 아래 터미널 경로는 연결 옵션의 보조 수단이다.

1. 설치된 Terminal·iTerm2·Ghostty 중 기본 터미널 앱을 선택한다. 선택은 다음에도 유지한다.
2. **로그인 명령 준비 · 실행하지 않음**을 누른다. iTerm2에는 명령만 입력한다.
   Terminal·Ghostty는 명령을 복사하고 앱을 연다. 직접 붙여넣고 Enter로 실행한다.
3. 처음 CLI에 로그인할 때는 개인 API 키를 터미널에서 입력하고 마스터 비밀번호로 잠금을 해제한다.
   기존 CLI 계정과 서버 설정은 그대로 사용한다. 대시보드는 로그인을 자동 실행하지 않는다.
4. **연결 상태 갱신**으로 확인한다. 연결 요청은 5분 동안 한 번만 유효하다.
5. 대시보드 연결 유지 시간은 5·15·30·60분 중 선택한다. 기본은 기존과 같은 15분이며
   변경은 다음 연결부터 적용한다. 마스터 비밀번호·API 비밀·BW_SESSION은 화면·파일·명령 인수에 저장하지 않는다.

이 설정은 대시보드가 세션을 메모리에 유지할 시간이다. Bitwarden 자체 잠금 정책과
SSH agent의 키 유지 시간은 별개다. 연결 해제는 CLI 로그아웃이나 agent 키 해제를 실행하지 않는다.
로그인한 터미널은 세션이 있는 작업 셸로 유지되며 환경변수 공급 명령도 여기서 실행한다.

## SSH 키 공급

**내 환경**에서 일괄 공급하거나 **원격 접속 → SSH agent**에서 수명·공급·해제를 관리한다.

사용자는 `bws` 명령을 실행하지 않는다. 기존 스크립트는 이전 흐름의 참고·호환 용도로 남기며 UI는 이를 호출하지 않는다.
키 공급 동작은 `ssh_domain.py`가 담당하고 `bw` CLI는 동기화·값 조회에만 사용한다.

평소에는 **등록된 키 모두 공급**을 한 번 누른다. 저장된 공급 목록의 키를 가져와 agent에 넣는다.
각 키의 결과는 공급 완료·기존 키 재사용·실패로 표시한다. 일부 항목이 실패해도 나머지 결과를 확인할 수 있다.
기존 agent의 같은 키는 재사용하고 TTL을 바꾸지 않는다. 추가하는 키의 유지 시간은 60~86400초다.

공급 목록에는 기존 `bws`의 `secrets.json`과 대시보드에 저장한 SSH 키 참조가 함께 포함된다.
같은 항목·종류는 한 번만 공급한다. 원본 목록을 다시 입력하거나 관리 설정에 별도로 가져올 필요가 없다.
`DOTFILES_SECRETS_MANIFEST`가 있으면 해당 목록을 사용하고, 없으면 `DOTFILES_DIR`·현재 저장소·
`~/dotfiles`·`~/.dotfiles`를 확인한다. `ssh-add`용 `note`·`sshkey`만 읽으며 파일 쓰기·환경변수
실행 항목은 실행하지 않고 제외 안내한다. 기존 `bws`도 계속 사용할 수 있다.

새 키는 **공급할 SSH 키 추가**에서 항목 검색 → 키 확인 → 공급 목록에 추가 → 변경 검토·저장한다.
키 확인은 선택한 키에서 공개키와 지문을 추출한다. 개인키를 일반 파일에 저장하지 않는다.
SSH 접속 대상을 선택하거나 `.pub` 파일을 저장해야만 공급할 수 있는 구조가 아니다.
추가 암호가 필요한 개인키는 자동 추출 경로에서 지원하지 않으며 기존 agent에서 준비한다.

현재 agent를 사용할 수 없으면 전용 agent를 만들고 소켓 경로와 터미널용 `SSH_AUTH_SOCK` 설정 명령을 보여준다.
SSH 연결 설정은 자동 변경하지 않는다. 기존 연결에 IdentityAgent가 지정되어 있다면 해당 소켓을 별도로 확인해야 한다.
**이번에 추가한 agent 키만 해제**는 이 대시보드가 추가한 메모리 키만 해제한다.
Bitwarden 원본·공개키 파일·GitHub 등록 키·기존 agent 키·접속 설정은 유지한다.
화면·서버를 닫아도 공급한 키는 유지 시간까지 남는다. 재접속 시 agent 소켓과 공급 기록을 다시 읽으며, 명시적인 해제는 대시보드가 추가한 키에만 적용한다.
강제 종료나 시스템 장애 때는 공급 시 정한 TTL이 남은 수명을 제한한다.

**공급 옵션**에서는 공급할 키 선택, 유지 시간, 조회 전 Bitwarden 동기화 여부, 기존 등록 목록 파일, 사용할 agent 소켓을 설정한다.
기존 목록 파일은 읽기만 하고 바꾸지 않는다. agent를 바꿔도 이전 agent에서 추가한 키의 해제 기록을 보존하며 다른 agent의 기존 키는 제거하지 않는다.
공급 기록에는 공개키·소켓·만료 시각만 저장하며 개인키·토큰·Bitwarden 세션은 저장하지 않는다.

## 환경변수 공급

1. Bitwarden의 Secure Note 또는 Login 항목을 검색하고 값 형식을 확인한다. 본문은 표시하지 않는다.
2. `GITHUB_TOKEN`·`API_KEY`처럼 대상 프로그램이 읽는 변수 이름을 지정하고 공급 목록에 추가한다.
3. 변경 검토에서 저장한다. 저장한 목록에는 항목 참조와 변수 이름만 들어간다.
4. 로그인한 작업용 터미널에서 화면의 `secret_supply.py --reference ID -- PROGRAM ARGUMENTS`를 실행한다.
   PROGRAM ARGUMENTS는 실제 프로그램·인수로 바꾼다. 대시보드는 임의 명령을 자동 실행하지 않는다.

값은 지정한 자식 프로그램의 환경에만 전달한다. 부모 셸·파일은 변경하지 않는다.
Bitwarden 세션, 다른 관리 변수와 다른 `*_TOKEN`은 자식에게 전달하지 않는다.
시스템·로더·인증 제어 변수는 공급 대상으로 허용하지 않는다. 현재 값은 한 줄 형식을 지원한다.
기존 HTTPS Git credential helper·gh/glab 인증은 유지하며 연결별 인증 선택은 Git 상세에서 관리한다.
기존 Jira·Confluence netrc와 Google 인증은 자동 교체하지 않는다.

## 구현 책임

- `secret_store.py`: Bitwarden에서 명시한 값 하나를 읽는 어댑터.
- `legacy_secrets.py`: 기존 bws 목록의 메타데이터만 읽는 어댑터.
- `secret_workflow.py`: 메모리 세션·검색·일괄 키 공급·공급 결과·agent 해제.
- `secret_session.py`: 사용자 터미널 로그인·잠금 해제와 일회용 대시보드 연결.
- `secret_supply.py`: 저장한 참조를 명시한 자식 명령의 환경변수로 공급.
- `auth.py`: 기존 SSH·HTTPS Git·API 인증 경로 유지와 키 검증·공급.

일반 비밀번호 관리 화면은 없다. 기존 일반 비밀번호 참조 데이터는 보존하고 자동 공급하지 않는다.
