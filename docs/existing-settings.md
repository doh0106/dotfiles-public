# 현재 상태 감지와 기존 설정 가져오기

환경 개요는 **현재 감지**와 **대시보드 관리**를 나눠 보여준다. 현재 감지는 로컬의 실행
파일과 설정을 읽은 결과이며, 대시보드 관리는 직접 선택한 설정과 가져온 기존 설정
참조다. 설치 감지를 근거로 기능을 자동으로 켜지 않는다. 새 컴퓨터 설정의 진행 기록은
대시보드 관리 설정에 대한 선택·실행 확인이며 이 컴퓨터의 설치 완료율이 아니다.

## 기존 설정 가져오기

1. 환경 개요에서 **기존 설정 검토·가져오기**를 연다.
2. Git 작성자의 적용 조건, SSH 주소·별칭·키 경로, 셸 원본 경로와 테마를 검토한다.
3. 필요한 항목을 선택하고 **선택한 설정을 참조로 가져오기**를 누른다.
4. 각 담당 화면에서 **가져온 참조**를 확인한다. 새 설정을 직접 작성하는 영역과 구분된다.

기존 설정은 **원본을 유지하는 참조**로 등록한다. 예를 들어 원격 URL 소유자로 작성자를
고르는 Git `hasconfig:remote.*.url` 규칙을 폴더별 `gitdir` 규칙으로 바꾸지 않는다. SSH의
ProxyCommand·Match와 셸 스크립트를 실행해 설정을 추측하지 않는다. 키·토큰 내용을 읽거나
복사하지 않으며, 참조 등록만으로 SSH agent·vault·계정 로그인 상태를 바꾸지 않는다.

참조는 `~/.config/dotfiles/dashboard/existing-settings.json`에 600 권한으로 저장한다.
설정 값 전체가 아니라 식별자·출처·검토 지문을 저장한다. 직접 관리하는 `settings.json`과
별개이며, 상단 변경 검토는 직접 관리 설정 초안을 저장한다. 원본 내용·위치가 바뀌면
**원본 변경됨·다시 검토**, 원본을 감지하지 못하면 **원본 감지 안 됨**으로 표시한다.
원본이 바뀐 상태에서 오래된 화면의 가져오기는 거부한다.

**관리 목록에서 참조 해제**는 등록만 해제한다. 원본 파일과 현재 설정은 계속 동작한다.
이 참조 목록은 기기별 경로를 포함하므로 다른 컴퓨터로 자동 동기화하지 않는다.

## 직접 관리 설정과 실제 적용

새 Git 연결, 폴더별 작성자, 셸·도구 선택은 각 메뉴에서 직접 편집한다. 참조로 가져온 원본
규칙은 이 편집기로 재작성하지 않는다. 원본을 수정하려면 표시된 원본 파일을 사용한다.

저장과 실제 적용은 별개다. 이후 사용자가 직접 configure를 실행할 때도 참조가 등록되어
있으면 기존 셸 로드 경로를 유지하고 새 선택을 추가로 읽는다. 기존 SSH 내용과 선행 규칙을
보존하며 기존 저장소의 원본 파일·키·토큰은 교체하지 않는다. 새 직접 관리 설정을 기존
규칙과 겹치게 만들었다면 실제 적용 전 생성 파일과 우선순위를 검토한다.

## 감지 범위

- Git: 사용자 global config와 로컬 include의 작성자·적용 조건. 저장소마다 로컬로 덮어쓴
  값이나 시스템 설정, 임의 실행 스크립트 전체를 수집하는 기능은 아니다.
- SSH: 사용자 config와 홈 안의 Include에서 정적 별칭·설정 참조. Match 조건을 실행하지
  않으며 실제 서버 로그인·네트워크 접속 성공을 보장하지 않는다.
- 셸: zshrc의 출처와 허용된 리터럴 ZSH/ZSH_THEME 값, 기존 셸 구성 경로. 동적으로 계산한
  값은 추측하지 않는다.
- 도구: 실행 파일 경로와 지원 도구의 설치 파일. Docker CLI 설치와 Docker 실행 상태,
  서비스 설정과 실제 인증 성공은 구분한다.

누락되거나 읽을 수 없는 설정은 다른 기능을 막지 않는다. 설계 미리보기는 실제 설정을
감지하거나 참조를 등록하지 않는다.
